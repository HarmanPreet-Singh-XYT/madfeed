# Design Taste

- Separates marketing styling from product styling: generous rounded corners are fine on the landing page but feel excessive inside the product/app itself, which should use noticeably tighter radii. Confidence: 0.75
- Avoids purple gradients in UI; prefers restrained, cohesive palettes, with light mode as the default theme and a theme toggle that actually works. Confidence: 0.7
- Product screens should be built from the shared UI component library (shadcn/ui primitives) rather than hand-rolled markup and ad-hoc class strings; consistency comes from the primitives, not from repeating raw HTML. Confidence: 0.7
- Treats default native browser controls as visible prototype tells in product UI — a bare `<input type="file">` "Choose File / No file chosen", an unstyled `<progress>`, or a native `datetime-local` field should be replaced with custom-styled equivalents (drag-and-drop drop zone, styled progress bar with cancel, a composed calendar+time popover, matching comboboxes) that match the rest of the design system. Expects a "real" picker even when the native one works. Confidence: 0.75
- Design proposals and audits must land in the product's existing brand language (its own tokens, type scale, palette), not an outside/generic design language borrowed from reference screenshots; re-states this as a standing expectation ("should match the branding") even when approving the same kind of work again. Confidence: 0.75
- Expects AI/extraction output to be shown inline in the source material it came from — the extracted spans highlighted in the original text (with machine-suggested and human-accepted marks visually distinct), plus each result's title and quote listed in the panel — rather than a side panel that only reports counts and a link. Calls the counts-only version not "insightful" or "interactive" even when the data behind them is correct. Confidence: 0.65
- Async/background work must announce itself with an unmistakable progress affordance (spinner/live status on the element that is filling in), not a calm sentence of muted text elsewhere on the page that reads as static content — otherwise he reports the loading state as missing. Confidence: 0.65
- Wants "public sources" / web research to serve competitor analysis specifically — surface whether a feature already exists elsewhere and how other companies build around it — rather than generic company facts or vague public-page summaries, which he dismisses as "weird stuff" and a misunderstanding of the panel's purpose. Confidence: 0.6
- Expects standard SaaS workspace/account navigation to be first-class and reachable, not buried: the workspace switcher should open a real menu that lists every workspace he belongs to and offers switching, "create a workspace" and "invite people", and team/workspace management should be enterable from the nav. An affordance that looks interactive but only reloads the page (or a management surface only reachable by typing a settings URL) reads as a missing feature, and he names established products (Mobbin, Linear, Vercel) as the benchmark for how it should work. Confidence: 0.6
- Judges UI by whether it reads as a finished product rather than a prototype, and will reject work that feels demo-like (hero banners, floating/loose chrome, detached primary actions, placeholder-feeling layout) even when it functions correctly. Confidence: 0.65
